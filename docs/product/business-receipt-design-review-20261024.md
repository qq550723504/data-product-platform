## 2. 发现与修正

### D1：后置产物仍可能成为来源见证的前置条件

基线 G2 引用 T01–T10，T06 同时包含“标准适用”和建单后才能产生的“本单确认”；此前只排除了 T11，仍可能要求未建单目标先提供本单草稿确认。T01 的新动作能力、T03 的 Case 固定绑定、T10 的平台接纳实现也不能由来源只读阶段提前完成。

修正：按来源只读、建单/修订、确认/签收、当前准备四个阶段说明清单用法。G2 只要求当前 READ 和目标/来源可核对性，不要求 Case、确认、签收、平台接纳模型已落地或写能力已授予；完整实现及后置办理证据仍归 G3–G5。创建不要求本单确认/签收，来源只读不生成 Core 接纳结论。对应新增 R45。

### D2：新写规则与历史/未决恢复没有完整分流

基线 R30 将非 DRAFT 一概拒绝，R23 的当前签收检查也缺少新写限定；若套在旧键重放上，会与既有“当前 READ 下恢复本人原成功回执”契约冲突。页面只列 UNKNOWN 查询，没有完整描述持续 NOT_OBSERVED 的受控原请求恢复边界。

修正：先恢复本人同空间且指纹匹配的 COMMITTED，再对无原回执的新写检查动作能力、状态、CAS、当前签收及来源。外部材料预查不得用失败结果抢先否定原成功；来源网络调用仍在业务锁外。旧成功返回原 resultingRevision/事实 ID，不再次移动当前指针。Create 没有既存 case 状态前置，previousCaseId 仅追溯。

持续 NOT_OBSERVED 的“恢复原请求”是原四个 Command 之一的原意图，不是只读动作或第五个 Command：未来必须另行启用写边界、本人当前授权、原人/空间/目标/key/body、原键锁重查及新写最终准入；关闭时仅可 GET 恢复已提交结果。不能自动换 revision/材料/键或清除旧 UNKNOWN。对应 R23/R30/R35 修订及新增 R46/R47。

### D3：历史来源失效可能被错误并入当前准备依赖

基线将接纳失效笼统映射为“当前准备阻断”，没有区分已被补正替代的旧签收和当前签收。如果 r1(e1) 已被 r2(e2) 替代，仅 e1 失效不应在 r2 无此依赖时制造 blocker。

修正：准备条件只走 Case 当前草稿/确认/签收的依赖闭包；历史成员独立展示，不做并集或 latest 推断。当前冻结成员仍失效则阻断，不静默丢弃成员；旧签收/提交/档案和其 hash 不改。r2 健康也不放行仍引用 r1 的旧 submission，后续审核保留精确 receipt 匹配。对应 R11 修订及新增 R48。

## 3. 静态闭包与执行边界

| 检查维度 | 本轮结论 |
|---|---|
| 来源与形成顺序 | 记录完整不等于可信收到；按阶段区分输入与产物，不要求先签收再证明可以签收 |
| 状态、补正与历史 | 新写与原成功重放分流；显式当前指针与追加历史分离；第一切片不扩展后续状态 |
| 幂等与恢复 | 同键原内容、当前 READ/主体范围、COMMITTED 优先、NOT_OBSERVED 不等于失败；受控恢复仍受写门禁 |
| 并发与事务 | 沿用 IAM→workspace 依赖 fence→原键锁→case→来源/成员的既有顺序；本地最终重读和远端检查点分开，不声明跨系统原子撤销 |
| 身份与空间 | 旧成功读取也须当前 READ 与原参与人范围；新写再检查冻结角色/动作能力，不给替任人或共享凭据接管 |
| 来源、实现与启用 | 实际来源、接纳事实模型、撤销窗口和运行授权仍是后续 blocker；文档一致不解除 G1–G8 |
| 验证 | 本轮只做文档一致性、相对链接/锚点、T/R/G 编号和 diff/范围检查；执行结果见精确提交的 PR closure，已有只读 CI 不冒充新签收验收 |

这三类修正均为现有契约的必要收敛，不新增实体、Command、状态、来源产品、锁服务或后台重试。当前作者有界文档复核无剩余一致性 blocker；业务/独立评审和新写入执行验证未被本报告替代。真实来源待定项继续由启用清单跟踪，不升级为当前开发范围。
