## 修复结果

| 问题 | 修复 | 保留的业务含义 |
| --- | --- | --- |
| 页面混用 Core、数据对象类名、RAW、DIAGNOSIS 等实现词汇 | 复用共享展示词典，将菜单、标题、徽标、动态计数、表单标签统一为业务名称 | 原枚举、路由、提交值和查询参数保持原样；未知状态不转为成功 |
| 测试编码、样例对象编号占据主视图 | 测试编码按需展开；已知预置验收对象显示“验收单、签收记录、验收档案”等分类及原序号 | 原编号仍用于保存、查询与历史定位；实际编号和人工材料依据不改写 |
| 模板引用、校验摘要和底层错误重复出现在主流程 | 收进“查看模板版本与校验摘要”“查看评测规则引用”“查看错误详情”等原生展开项 | 原始规则引用、错误与代码证据可查看，历史报告仍按明确身份读取 |
| 同一用途、验收条件在主卡片和侧栏重复展示 | 主卡片保留完整条件，侧栏集中展示范围、版本与关联信息 | 不改变确认范围和执行准入条件 |
| 英文状态容易被误解为业务完成 | `ISSUED` 显示“授权已释放”，`UNKNOWN` 显示“无法确认”；扫描异常显示“暂不可用、已中断” | 授权释放、收到材料、验收通过、归档分别保留，不相互推定 |
| 错误处理说明过长或挤占视觉重点 | 通用原因按需展开，权限不足、越界、未配置、缺失依据仍立即可见 | 查询失败不显示零条或成功，独立分区继续显示各自结果 |
| 状态翻译可能命中材料编号片段 | 完整材料编号优先保持原文，例如 `STORAGE-UNAVAILABLE`；仅已知预置编号使用明确展示别名 | 不改写人工依据，不改变 React identity、表单值或后端身份 |

| 2 | Agent 工作台、任务、修复计划、质量详情 | 4 | 阶段与输入业务名称、历史计划只读、确认和意图入口继续关闭 |
| 3 | 已接入资产目录与明确版本 | 2 | 原始编号可查，成果版本与质量结论分别展示 |
| 4 | 待办工作台、发布历史、认证历史 | 3 | 历史事实与当前资格区分，失败分区不掩盖其他结果 |
| 5 | 交付记录、证据档案 | 2 | 授权释放不等于收到或验收，未配置不冒充零条 |
| 6 | 标准与验收责任 | 1 | 标准来源和责任未配置时保持无法确认 |
| 7 | 发布证据链 | 1 | 缺失或跨空间对象不回退其他历史对象 |

上述 67 个状态是预览页面检查范围，不代表全部企业身份路径已完成真实来源验收。当前预览未启用企业身份服务；真实人员目录、责任来源与收件材料仍未配置，这些场景没有被本轮启用。
