# RP 凭据绝对到期测试修复

2026-10-24，定位基线 PR #363 `c7f8a215359c0c131a5ab2b4b93be0c782a8af97`。用户单独授权修复 RP 到期单测、补齐回归并核对最新提交 CI；不开发业务功能。真实来源仍 UNCONFIGURED，业务写入口关闭；保留原库和 Agent API，不接模型、不派发真实执行，Draft 不合并、不部署。

## 根因与复现

原失败见 [Live Core job 120897303335](https://github.com/qq550723504/data-product-platform/actions/runs/40102474985/job/120897303335)：构建前运行既有 RP 单测，凭据到期用例在 callback 抛出 `Browser identity unavailable`，没有进入浏览器验收。

用例原先返回 `expires_in=1`，要求 callback 先成功，再等待1100ms检查到期。所用成熟 SDK 在接收响应时记录 `Date.now()+expires_in*1000`，`expiresIn()` 返回剩余毫秒除1000后向下取整。其间只要前进1ms，剩余999ms就变成0；RP 按既有策略拒绝零剩余有效期，因而不一定能建立用例要求的会话。这是成功路径依赖真实时钟粒度的测试竞态，不是应放宽的认证判断。

在原用例中仅让 `Date.now()` 每次前进1ms，即稳定复现相同 callback 失败，发生在1100ms等待之前。修复未改生产 RP、SDK 或存储实现，也未增加宽限期、刷新或兼容兜底。

## 修复与回归

- 使用 Node 原生测试时钟，只控制 Date，不接管网络定时器；成功路径使用明确60秒期限，没有真实等待。复用现有 TLS OIDC/PKCE/JWKS 夹具及真实 SDK，无新依赖、时钟服务或产品 Port。
- 断言会话截止时间固定为签发时点+60000ms；到期前1ms仍可读，到期瞬间和之后1ms均拒绝。当前资格查询不延长原绝对期限。
- 到期检查故意让存储继续返回原加密会话，证明拒绝由 RP 自身保证，不能只靠存储 TTL 掩盖边界错误；到期后不再次查询身份源、不调用 token endpoint。
- 增加零、负以及正数1秒经 SDK 取整归零的拒绝回归；全部在 authority lookup 之前拒绝，不落 session。保留真实 SDK 解析和校验，不 mock `expiresIn()` 的实现。
