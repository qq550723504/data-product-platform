# 领导演示讲解与重演

建议8分钟。入口：<http://127.0.0.1:4193/>。使用新的 Edge 标签页，从首页开始；演示身份和所有 DEMO 编号均为合成记录。当前无需登录，不启动原认证网关。

## 讲解顺序

| 时间 | 页面与操作 | 建议讲解 |
|---|---|---|
| 0:00–0:45 | 首页，指示顶部边界、三个业务中心与侧栏 | “这版统一了治理、开发交付和 Agent 的工作界面。今天展示操作路径和责任边界，使用合成数据；真实来源尚未配置，业务写入口关闭。” |
| 0:45–1:30 | Agent 工作台 → 诊断一个质量问题 → 查看版本 → 核实上下文 | “先选明确数据与版本，再查看依据。当前 Agent 使用确定性模板，不连接模型，也不执行修复。” |
| 1:30–2:15 | 两条评测历史 → 选择当前失败评测 → 展开证据引用；可选旧通过报告并刷新 | “报告是某次评测的独立结论。这个合成样例有一条负能耗失败发现；刷新或查看旧报告不会将它替换成最新报告。修复与质量评测仍是不同活动。” |
| 2:15–3:15 | 返回 Agent 工作台 → 审阅修复计划 → 最近任务选记录 → V2 修复计划 → 上下文来源链接；可看 V1 历史 | “计划明确问题、评测、数据版本、工作流和输入。确认与动作意图分别办理；本预览只审阅，保存和确认都关闭。展示的计划、绑定与指纹是静态样例，不是实际办理收据。” |
| 3:15–3:45 | 首页 → 业务验收 → 查看验收 | “接下来看独立的业务签收样例。它不是前面 Agent 数据的交付结果；同样没有真实传输。缺少完整签收，验收不能提交。” |
| 3:45–4:45 | 核对签收 → 收件方代表 → 部分收到 → 完整收到，各存一条 | “签收记录说明收到情况。补正会追加新记录；收到不代表满足验收标准。这里的角色切换只用于演示，正式办理需要可信多人身份与责任来源。” |
| 4:45–6:00 | 提供方提交 → 验收人一项未满足后退回 → 提供方重新提交 → 验收人逐项通过 | “每次提交冻结当时的标准与签收。提供方不能代替验收人决定；退回与重新提交保留原材料和结论。演示标准分别来自合成合约、业务需求和验收约定。” |
| 6:00–7:00 | 归档经办人 → 冻结档案 → 刷新 → 追溯签收 | “验收通过和归档是两个动作。档案明确引用哪次提交、哪条签收、哪些标准与原决定；证据快照本身不能代替业务验收通过。” |
| 7:00–7:40 | 可选：返回验收 → 验收人追加决定作废 → 查看原档案 | “错误决定通过后续处置作废，历史通过与原档案仍保留。页面明确提示当前决定无效，不能用历史档案继续声称验收有效。” |
| 7:40–8:00 | 回到能力清单 | “当前已完成界面、只读接入基础和两条受控演示。真实试点场景、接收组织、责任团队与来源还待确认；确定后才按既有启用清单评审后续实施与权限。” |

时间只有5分钟时，保留首页、质量报告/任务上下文、完整签收、逐项验收、归档追溯五段；退回与决定作废用截图讲解。不为压缩时间跳过逐项核验，不宣称 Agent 已执行或真实验收已通过。

## 业务路线的确切操作

1. 首页点击“业务验收”，再点“查看验收”。提交按钮应禁用。
2. 点击“核对签收记录”。演示办理身份选“收件方代表”；收到情况选“部分收到”，填写 `DEMO-LEADER-PARTIAL` 与说明，保存；进入业务验收，仍不能提交。
3. 再进签收，追加“完整收到”，依据 `DEMO-LEADER-COMPLETE`，填写说明并保存。旧签收继续存在。
4. 回验收，切换“提供方经办人”，确认冻结并提交。切换“业务验收人”，把“统计期间符合需求”选为未满足，填写说明后退回。
5. 切回提供方重新提交；切换验收人，三项逐一通过，写说明，确认验收通过。应保留两次提交、一条退回与一条通过决定。
6. 切换“归档经办人”，冻结验收档案；刷新应仍为同一档案。可追溯归档引用的签收，再回到明确提交的冻结材料。
7. 可选异常：切换验收人，追加决定作废及说明，再查看已归档记录。原决定保留，后续处置与“当前验收无效”提示可见。

## 本机启动与自动重演

在 aq1 工作树根目录执行；不运行旧预览的数据库准备、seed、OIDC 或网关启动脚本。

```powershell
# 首次构建独立输出并启动；端口占用时会停止启动，不会抢占旧进程。
& ./tests/leader-demo/preview.ps1 -Build

# 已有该隔离构建时只启动。
& ./tests/leader-demo/preview.ps1

# 新 Edge 上下文自动走两条路线，结果写入新的 .data/leader-demo-runs/<时间-随机值>/。
node tests/leader-demo/acceptance.mjs

# 如需准备新交付包，显式指定尚不存在的仓库内目录；已存在目录会被拒绝。
# node tests/leader-demo/acceptance.mjs --output docs/product/leader-demo-new-review

# 仅停止本演示清单中 PID、启动时间、命令、端口均匹配的两个进程。
& ./tests/leader-demo/preview.ps1 -Stop
```

依赖沿用 `apps/web` 与 `tests/browser` 已安装版本及本机 Microsoft Edge。缺依赖时，在新的干净 checkout 按各自锁文件安装；不为重演覆盖当前已有 node_modules。自动重演通过用户批准的 Playwright Edge 完成，使用全新浏览器上下文，结束后关闭自身会话；不影响原 Edge 会话。

重演默认写入唯一的新目录，不覆盖任何已交付截图或 JSON。显式 `--output` 也必须是本 checkout 内尚不存在的目录；创建新交付包后，先检查 verdict、逐步结果、原始截图及摘要，再更新文档链接，保留旧包。`worktreeReference` 是捕获开始时的提交/文件摘要，不是运行构建的身份认证；`unchangedDuringCapture` 仅证明捕获期间所列文件未变。PNG 的 SHA256 用于核对同一包的文件，不能证明真实业务事实。真实原件、个人资料、凭据均不作为重演材料。

当前交付截图与21步验收见[交付指南](leader-demo-closeout-20261025.md)。评测历史在演示包中只有两条，逐条均可打开；分页压力场景由独立 CI 夹具负责，不在现场讲解中要求翻页。

## 现场恢复

| 现象 | 处理 |
|---|---|
| 出现账号框或身份页 | 核对地址4193与顶部演示标识；不要使用原4189认证网关，不输入企业凭据 |
| 4193/4493已占用 | 保留现有进程；核对本演示 `.data/leader-demo-20261025/processes.json`。只有身份完全匹配才能用本脚本停止 |
| 本地业务样例已办完 | 仅在新演示标签页点“重置演示”并确认；不会清空 Agent API 或数据库。不要重置他人的标签页 |
| 浏览器存储不可用 | 页面提示“本地会话存储不可用”；当前修改仅在内存中，刷新会丢失本次修改或恢复此前成功保存的状态。停止办理，改用已交付截图；不声称保存成功 |
| API查询失败 | 显示 UNKNOWN；不替换为最新对象或本地成功状态。可用截图继续讲解，故障恢复后单独重验 |
| 构建/启动失败 | 保留日志与进程记录，不自动删除数据库、旧构建或强制关闭端口 |

原库、现有 Agent API、旧预览、身份环境均不在此脚本的启动/停止清单内。来源仍未配置；正式业务写入、模型、真实执行及 PR 合并/部署均未授权。
