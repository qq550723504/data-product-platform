| Gate | 责任 owner | 必需证据 / 通过条件 | 当前状态 |
|---|---|---|---|
| G0 契约与范围 | 业务、Acceptance、Evidence、IAM、Web | 五项文档一致；四个 Command 仅 DRAFT；职责/来源/历史/UNKNOWN 边界获明确评审 | 文档已整理；业务与独立评审 NOT_RUN |

| G2 真实来源只读见证 | 各来源 owner、验收方 | 另行授权后，以明确空间与既有 ISSUED 交付/版本核对当前 READ/人员/目标责任、标准及适用；核对来源能否提供 T07–T10 及 T12 的原件/来源记录，不要求本单草稿确认、签收或平台接纳模型已落地 | NOT_RUN；不生成签收或可信接纳结论 |

| G4 独立技术验收 | 验收方、DB/安全 owner | 新独立库的 Domain/Application/Adapter/真实 PG/HTTP/Browser；异常矩阵 R01–R43、R45–R48，后续 R44 独立归属；无 synthetic 正式放行开关 | 新写入 NOT_RUN |
| G5 历史及恢复复核 | Acceptance、Evidence、Web | header/member 不可变、补正/当前依赖、撤销顺序、同键幂等、commit 后丢响应与重启恢复；旧成功可读与新写恢复分支独立；证据不含 secret | 新写入 NOT_RUN |

任何必需项缺失、FAIL 或 UNKNOWN 都不允许启用；文档完成不将 G0–G8 自动改成 PASS。真实资料、签收/验收事实和技术测试证据分别留证，不以截图或 EvidenceSnapshot 代替业务接受。

G2 验证原始来源能否满足契约：T01 只要求本次 READ 资格，T03 读取目标责任而非尚不存在的 Case 冻结成员，T06 只核对标准适用与确认责任；其本单确认只能在未来建单后的 ConfirmAcceptanceBasis 产生。G2 不要求平台接纳模型已实现，也不能要求先产生 T11 签收办理依据来证明可以签收。T06 的本单确认、T11 及 T12 中的业务办理历史由未来 G4/G5 的隔离办理见证；可信接纳事实/Port 在 G1/G3 定稿与实现。G2 的现场只读结果不自动生成 Core 接纳或 RECEIVED，后置产物不得成为前置门禁。

## 3. 来源选定时只需补的决策

| 决策 | 必须明确 | 当前值 |
|---|---|---|
| 实际来源及责任人 | IAM/目录、代表责任、标准、材料各自系统/受控流程和业务批准人 | 全部待定 |
| 接口与身份边界 | 只读协议、固定服务端地址、最小权限、稳定人员/记录身份、空间与 party 映射 | 待定；不接受客户端任意 URL |
| 原件与接纳 | 可核验的内容版本/hash、原记录者与接收声明、接纳规则及强类型依据、保留/撤销 | 待定；不可用普通上传或 metadata 布尔值顶替 |
| 撤销时效 | 远端检查点/允许窗口与期限，断网拒绝策略，本地接纳处置与签收的串行化 | 待定；不宣称远端撤销与 PG 原子提交 |
| 最小只读试点 | 一个空间、一笔既有真实 ISSUED 交付、一个实际成员版本、六类明确责任 | 待定；不为造正例派发真实交付 |

先补一条可验证的业务链，不要求一次连齐全企业系统。但该试点依赖的每一项必需依据都必须完整，不能靠缩减责任或材料条件降低首版准入。

## 4. 将来允许申请的首个动作范围

沿用第一切片四个显式 Command：CreateBusinessAcceptance、ReviseAcceptanceDraft、ConfirmAcceptanceBasis、RecordBusinessReceipt。前提是 G0–G7 已满足，并有另行实施/运行授权；本文件不授予该授权。

- Create 为明确成果创建新 DRAFT；修订/确认/登记或补正这三类新写仅限本单 DRAFT。previousCaseId 只作追溯，不继承旧状态。标准确认与签收可分别办理，准备齐全仍停留 DRAFT；已提交原回执恢复不是新状态迁移。
- 只授予实际角色所需的 READ + 单项动作能力；服务端每次重新校验身份、冻结责任及动作依赖，不把可见按钮当授权。
- 不包含 Submission、撤回/取消、验收通过、归档/作废、代办、附件上传、电子签章或新交付；这些仍归后续独立切片。
- 不使用原库做试写，不扩大 Agent token 或注册 Agent 执行消费者；模型/真实执行继续关闭。

## 5. 停用和未知结果恢复

将来启用方案必须能停止**新的**命令分发，包括可能首次产生业务事实的“恢复原请求”POST，同时保留已提交事实、审计和回执。仅查询旧成功的 GET 恢复仍须当前本人/空间 READ，且不要求本单仍 DRAFT 或原签收/材料仍是当前版本；失去 READ 时拒绝，不为了恢复临时授予共享账号权限。持续 NOT_OBSERVED 不授予重新发送资格；未来恢复原请求须写运行边界开放、本人重新授权，并由原键锁分流到旧成功重放或完整新写校验，不能借“恢复”绕过门禁。

| 触发 | 必须采取的措施 |
|---|---|
| 来源被撤销、内容不符、责任冲突或越界泄露迹象 | 停止实际受影响的新写，按当前依赖定位影响范围；旧签收专属材料失效不自动阻断已脱离该依赖的新签收，历史 outcome 不改 |
| 数据库/回执写入异常或不确定响应 | 保留原意图/key/body；不能在关闭入口时宣称在途命令已回滚，按原回执恢复 |
| 已提交后需要业务更正 | 仅授权角色通过显式追加补正/后续处置；不使用 UPDATE/DELETE 或 migration down 擦除事实 |
| 旧配置或构建回退 | 不让旧版本重解释新事实；先评审 schema/契约兼容与在途恢复，不以回滚抹除 UNKNOWN |

当前未实施写入，因此不存在可执行的启用/回退命令。本轮完成后仍是“设计可评审，来源未配置，写入禁用”；后续每一步均按其实际授权和证据单独推进。
