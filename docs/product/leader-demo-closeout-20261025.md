## 审查与修复

1. 新版壳原先固定显示“Core 持久化”和“计划与确认由服务端保存”。合成预览现通过服务端的显式 `synthetic-readonly` 模式显示来源、写入关闭及未配置状态；常规部署默认行为保留，不修改真实 API 认证与权限。
2. Agent 场景卡原先是不可操作的展示区域，现使用原生 Link 进入现有质量上下文和任务页。未新增业务对象、Command 或运行能力。
3. 任务上下文原先回到空的质量选择页，现携带计划自己的 `sourceVersionId/sourceAssessmentId`。明确来源与历史报告不会丢失。
4. 首页“同一成果版本”文案与独立验收样例不一致，已明确治理流水线与独立业务验收分别保留记录。
5. 通用分页夹具原先只有通过记录，与负能耗修复样例不一致。新增隔离演示场景，使失败发现、维度结论、报告、证据与计划引用一致；这是合成样例修正，不是对现有业务历史的更改。
6. Agent 通用徽标样式覆盖了已有语义颜色，使 FAIL 也显示为绿色。移除通用颜色覆盖，保留原有成功/警告/失败/中性样式；浏览器回归核对失败与成功的文字及背景颜色不同，并确认只发生 GET 查询。

复用检查：沿用仓库 Next 壳、Agent BFF/控制器、CoreQualityView、DemoProvider/sessionStorage、现有 HTTP 夹具及 Playwright。未增加依赖、持久化、身份/权限引擎、工作流运行时或第三方服务。明确 API 数据源来自哪里应由部署边界传入，不能再由“用了 API 组件”推断为真实 Core 事实。
