## Core conclusions

1. Agent HTTP authenticates before repository access; workspace is resolved through the existing principal resolver. Task writes additionally bind actor and subject to task creator. Top-level duplicate/unknown JSON fields and cross-command fields are rejected. Agent quality context checks version/dataset/workspace consistency and returns whitelisted metadata; no source payload or storage URI is exposed.
2. Q2 stores platform planning facts only. `Handle` calls read-only owner preparation, not Detect/Assign/Execute/Retry/Recheck. Fresh source/template/provenance checks occur for approval and action-intent acceptance. Repair preparation reuses the existing Remediation validator and locks its case/job dependencies; it does not invent an owner receipt. Only the first action slot is accepted, so absent Q3/Q4 owner receipts cannot enable execution or recheck.
3. Commands and task-control changes share the task lock and revision; CREATE serializes its scoped idempotency key. Same-key replay performs authentication and ownership checks, then returns its original receipt before current revision/state checks. Receipt, task/plan/approval/intent, Audit, Evidence and outbox commit in one transaction. STOP cancels only Q2 REQUESTED intents; no dispatched state exists in this migration.
4. Plan membership takes the plan row lock; finalization is an UPDATE of that same parent and validates exact SQL-reconstructed header/members plus content digest. A deferred trigger prohibits committing DRAFT plans. Frozen header/members and history facts reject mutation. Down locks all affected tables before checking history. Both new dataset-version FK relations install structurally valid lifecycle admission guards and remain unreleased demand.
5. Producer routing freezes `agent-action-dispatch`; the current worker profile omits the unimplemented route. Existing dispatcher honors persisted obligations and fails an Agent claim without confirming/publishing it. It neither starts real Agent dispatch nor silently erases the obligation. Future Q3/Q4 handling still requires task/current-identity/owner rechecks before any work.
6. Next requires an incoming request Bearer for authority and every write, validates same-host Origin, and honors independent UI/Core switches. Deployment read credentials authorize only read paths. The normal browser stays read-only without a trusted proxy; the documented Caddy pilot supplies that authentication boundary. Receipt processing retains original pending key/body for unknown outcomes and settles saved facts before independent GET refreshes.
