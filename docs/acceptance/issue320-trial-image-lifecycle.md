# #320 trial image ownership and cleanup contract

## Goal and ownership

This change manages only newly built Hop/MinIO image references in the finite
postgres-ingestion harness. The run has one writer, a fresh UUID, an exclusive
new output registry, and a separate random image-owner marker. Before build it
records the run-owned tag and retention intent. Docker build adds the run,
retention and owner labels; successful inspection records the actual full ID.
Canonical digest refs generated by the build in that same repository are also
resolved to the actual ID/ownership and bound explicitly. Foreign or subsequently
added digest refs are not adopted. This supports Docker's two native image stores;
it is not historical-row compatibility.
These labels are local ownership markers, not authentication credentials.

The registry is a current projection; a separate append-only event file records
build intent/binding and cleanup decisions. Partial setup keeps its ownership
record. No command discovers old trial tags, adopts previous registry files,
or reconstructs ownership from a name prefix alone.

## Retention and cleanup boundary

| Object | retain | non-retain |
| --- | --- | --- |
| Run-owned Hop/MinIO image reference | RETAINED; no image mutation | Eligible only with matching tag, actual ID, all ownership labels, exact build-bound canonical refs, no additional tag/digest, and no container consumer |
| Missing owned reference | Still report retention intent | Distinguish never-created, already-absent and missing-tag/image-still-present |
| Repointed tag, unknown owner, additional references or consumer | Preserve | BLOCKED; preserve and expose reason |
| Docker inspection/delete error or uncertain result | Preserve | UNKNOWN/FAILED; never report full cleanup PASS |
| Shared aliases, public/base images, build cache | Preserve | Preserve; no image-ID deletion, force, parent pruning or broad prune |
| Existing retained environments, named volumes, objects, backups | Preserve | Outside the cleanup authority |

Containers, networks and temporary credentials retain their existing
run-specific lifecycle. Their receipt entries are separate from image refs.
The image manager never stops/removes containers or touches volumes/files of
other runs. Existing B1 anonymous source-volume cleanup is not exercised by
this change's native image validation. B3 and the image-isolation regression
explicitly retain their images as well as their existing runtime resources.

Non-retained cleanup runs after the run's own containers have been handled.
It checks **all** containers, including stopped consumers, rechecks the image,
then asks Docker to remove only the exact owned tag, without force and with
`--no-prune`. It verifies the outcome and records tag and image presence
separately; removing a ref is not a claim that all storage/build-cache bytes
were reclaimed. A failed build with a matching ownership-labelled image can
bind its observed ID before cleanup; missing/malformed ownership fails closed.
Repeated cleanup is observable and idempotent.

## Concurrency limit

Docker's image deletion API has no conditional tag-to-ID compare-and-delete.
Inspect followed by delete is not a global Docker authorization fence. This
contract requires the single run writer to exclusively mutate its fresh tag
namespace throughout build/use/cleanup; other harness runs mint different UUIDs
and ownership-labelled configurations. An administrator or unrelated Docker
client that concurrently retags that namespace is outside this supported
boundary. Observed changes block cleanup; no global-daemon race immunity is
claimed. A daemon that cannot provide this exclusive namespace must retain
the run instead. No cleanup service or shared-daemon garbage collector is added.

Sources: [Docker image rm](https://docs.docker.com/reference/cli/docker/image/rm/),
[Moby image deletion](https://github.com/moby/moby/blob/master/daemon/containerd/image_delete.go).

## Reuse and validation

Reuse Check: the existing Trial UUID/retain lifecycle, Docker CLI ownership
labels/inspection/non-forced deletion and Python stdlib suffice. Docker owns
image/layer reference accounting. No new storage/queue/workflow/GC framework,
SDK or fork is introduced. This is a finite harness ownership rule, not Core
business state or a new commodity runtime.

Required checks cover retained, absent, repointed, foreign ownership, additional
refs, stopped consumers, partial setup, daemon failure, delete failure and
idempotent retry. Native checks may build/delete only fresh isolated image refs
from this request; original retained services/shared aliases/volumes/backups are
never cleanup targets. Mocked checks and native observations remain distinct.

command TimeoutExpired/OSError could escape storage/B2 finally before business
and cleanup receipts were written; Trial could also leave an attempted component
labelled NOT_RUN. The fix shares a finite receipt observer across these entry
points: initialize FAIL/NOT_RUN, record UNKNOWN before each action, capture only
safe exception type, continue subsequent components and always save the receipt

does not authorize any new cleanup target or add a GC runtime.
